01The core move

The trick: the medium (wire, fiber, CPU, disk head) is shared, and every user gets a slicing rule — by time, frequency, wavelength, or packet — agreed on by both ends. There is no magic; the entire art is choosing the slicing rule.

02Three slicing rules, one idea

1Time — TDM

Each user owns fixed time slots on the wire, in rotation. The telephone standard: 30 voice channels, 125 µs frames, one sample each. Your CPU time-slicing is exactly this: the scheduler hands the core to each thread in rotation.

2Frequency / wavelength — FDM / WDM

Each user owns a band that runs all the time. Radio stations never collide because they're on different frequencies; fiber carries 80+ wavelengths at once (DWDM), each a full gigabit pipe.

3Content — statistical

No reservations. Packets carry a destination tag and grab the wire whenever they exist. Data is bursty — someone is usually silent — so the average user gets more than their TDM slot. This is the whole internet, and it is why the web works at all.

03Watch the waste appear and vanish

Same four users, same wire. In TDM everyone keeps a slot forever — flip a user off and their slots turn into pure waste. Statistical multiplexing hands the wire to whoever has data. Toggle users, switch modes.

The one trade

TDM gives everyone a guarantee — your slot is yours even in a storm of traffic. That guarantee is the price: silence burns slots.

Statistical gives no guarantees — a bursty neighbor can starve you — but the aggregate carries far more load. Real networks stack both: statistical on top, with queuing (packet buffers) and traffic shaping as the safety net.

In your codebase the same choice recurs constantly: a fixed worker pool (TDM) vs. an event loop with epoll (statistical) — which is exactly why epoll scales to thousands of connections and thread-per-connection doesn't.

04Where you already know this

CPU scheduling

The core is one wire. Round-robin is TDM; priority scheduling is a policy on top. Context switching is the demux — expensive enough that people built epoll to avoid paying it per connection.

I/O multiplexing

select/poll/epoll: one thread multiplexes thousands of sockets. The event loop is the mux; readiness bits are the tags. This is Node, Redis, and nginx in one sentence.

GPU & memory

Time-sliced multi-GPU, spatial partitioning of compute, and virtual memory: every process's pages multiplexed onto physical RAM by a translation table — the demux is the TLB.

Multiplexing = shared medium + an agreed slicing rule + a demux that reverses it. Everything else is a variation on the slot. Simulator: 16 slots × 4 users, round-robin allocation, no queuing or contention shown — statistical can starve a user under real overload.
